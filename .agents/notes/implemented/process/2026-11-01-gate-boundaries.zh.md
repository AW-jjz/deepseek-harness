# Agent Note: 两道闸现在说明自己读不了什么

Status: implemented

[English](2026-11-01-gate-boundaries.md) | 中文

## 问题

仓库里两道闸在两行不属于它们目标的行上触发，其中一处的修法不是改那一行。

`verify-repository-references` 拒绝粘进维护文件的提交标识。它把候选定义为能唯一解析到本地对象库中某个对象的 7–40 位十六进制串，于是**十进制数**也可能合格：`python/sdk/uv.lock:113` 里为一个 Pillow wheel 记录的 `size = 6344383`，恰好是某个提交的唯一前缀。按闸自己的规则这是真命中，作为引用却无意义——没有人会因为钉住某个 wheel 的体积而引用一次提交。它同时让判定依赖某个克隆恰好持有哪些对象。

`test:snapshot:refresh` 用当前这次运行产出的内容重写已提交的快照夹具。在 Windows 上那一次运行产出的是不同的字节：会话 header 记 `pwsh` 而语料记的是 `bash`，路径也保留录制平台的形式。在工作目录引号修好之前，这个危险被掩盖着——语料在 Windows 上解析就失败，refresh 走不到写回那一步。解析修好之后，同一条命令会安静地把 Windows 输出提交进其他所有平台都要重放的基准。

## 决定

两道闸各自说明自己不考虑哪种读法，而不是靠推断。

**纯十进制串是数。** `isCommitShaped` 要求缩写的候选里含有字母，于是 `6344383` 是体积、`6344383a` 是引用。完整标识仍然无歧义——40 位 SHA-1 每一位都落在 0–9 是 `(10/16)^40` 的巧合——所以粘贴的完整哈希仍会被拒。被接受的漏判写出来而不是藏起来：7 位全十进制的缩写会通过，而任何形状规则都无法把它与本不该读成引用的数字分开。

**refresh 只在录制语料的平台上跑。** `scripts/assert-snapshot-refresh-platform.ts` 排在三处 refresh 脚本之前，凡平台不是 `linux` 即以 1 退出，并点名在任何平台都能跑的 replay 命令。没有环境变量开关：常量就是那一行需要改的可见代码，这与错误码闸给自己数量留的摩擦力是同一套做法。

## 被否的方案

- **把锁文件从引用闸里排除。** 它只盖住这一例而不是这一类：表格、图表或 JSON 夹具里的十进制字段同样会撞，而豁免锁文件会停止拦截真正粘进锁文件的哈希。
- **给候选设最短长度。** wheel 体积能到八位、计数能到十二位，门槛要么照样撞，要么开始忽略真实的短形式。
- **把平台判断放进 `vitest.snapshot.config.ts`。** 单元测试以显式 `mode: 'refresh'` 调用套件；配置层的拒绝要么漏掉它们，要么把它们打红，而脚本恰是人真正触发 refresh 的那个面。
- **让 refresh 把平台归一化掉。** header 是一次会话拥有过哪些工具的记录，语料的价值就在于重放是与真实跑过的东西比对；归一化等于为了让写者好过而删掉证据。

## 后果

引用闸不再因十进制字段而依赖某个克隆对象库的偶然内容，同时它报出的集合变小了：全十进制的缩写形式现在对它不可见，这一点写在这里，而不是留给以后当意外发现。

refresh 脚本改为快速失败而不是改写基准：在 Windows 检出上，链条里的第一条命令打印原因并在 Vitest 启动前以 1 退出。真需要 refresh 的人必须在 Linux 上做，或者改那个常量，而那次改动是可评审的 diff。

两道闸的全量形式都不变，因此 `doc-sync` 与 CI 读到的政策与贡献者读到的同一份。

## 证据

- `scripts/verify-repository-references.spec.ts` 覆盖十进制字段、同一串带字母的形式，以及一个七位前缀全为十进制的真实提交（`git cat-file -t` 证明该对象是 commit，扫描不报任何东西）。
- `scripts/assert-snapshot-refresh-platform.spec.ts` 钉定放行的平台与拒绝文案。
- 在 Windows 上 `npm run test:snapshot:refresh` 在 Vitest 启动前就以 1 退出，`git status` 看不到任何夹具写入。
